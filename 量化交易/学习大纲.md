# 量化交易 · 学习大纲

**起点**：零金融基础，看不懂 K 线，没有证券/期货/交易所账户。
**目标**：从零搭出一个能跑通「数据 → 回测 → 模拟盘 → 小资金实盘 → 监控」全链路的量化交易平台。
**方法**：不先读书再动手，也不裸写代码。**每一章绑一个可验收的产出**，金融常识和统计陷阱挂在这条工程主线上同步吸收。

> 量化交易里几乎没人靠看图赚钱——看图是主观交易者的活儿。量化看的是分布、统计量、收益归因。零金融基础不是障碍，**判断不了"回测哪里是假的"才是障碍**。这套大纲的每一章都在防这件事。

# 一、三条并行的轨道

| 轨道           | 内容                                     | 什么时候学              |
| ------------ | -------------------------------------- | ------------------ |
| **A. 市场常识**  | 买卖盘、限价/市价单、滑点、手续费、复权、做多做空、保证金、强平       | 第一章集中补齐，2~3 天，够用即可 |
| **B. 统计与陷阱** | 收益率分布、波动率、夏普、回撤、未来函数、过拟合、幸存者偏差         | 跟第三、四章同步，边写引擎边学    |
| **C. 工程实现**  | 数据管道 → 回测引擎 → 策略 → 风控 → 实盘网关 → 对账 → 运维 | 主线，占 80% 时间        |

关键原则：**A 和 B 不单独读书，而是挂在 C 的每个交付物上。**写完复权代码，自然就懂什么是复权——比看三天书管用。

# 二、市场选择与技术栈

## 市场：加密（第一阶段）

选择理由不是"好赚钱"，而是**零行政摩擦**：

| 市场 | 历史数据 | 回测 | 模拟盘 | 实盘 |
| --- | --- | --- | --- | --- |
| **加密** | 免费（交易所 REST + 历史数据包） | 不需要账户 | Binance Testnet，**邮箱注册即可，无 KYC、无资金** | 邮箱 + KYC，最低 $10 |
| 期货 | 部分免费，主力连续需自己拼 | 不需要账户 | 必须在期货公司开户（身份证 + 适当性测试） | 商品期货 5000 元起 |
| A 股 | 免费（AkShare / Tushare） | 不需要账户 | 需券商账户 | 需券商 + QMT/Ptrade，通常 50 万门槛 |

前 3 个月的技术工作**一个账户都不需要**。加密能当天跑通"数据 → 信号 → 下单 → 看盈亏"的完整循环，之后把同一套架构换到期货上改动很小（见第十章）。

## 技术栈

- **研究和回测**：Python（`pandas` / `numpy`）。量化领域的生态事实标准，两天上手。
- **回测引擎**：自研事件驱动（要学原理，也要能扩展）。
- **服务端与调度**：Java（复用已有工程能力），或直接用 Python 的 APScheduler 起步。
- **存储**：Parquet 分区文件起步，数据量大了再上 ClickHouse。

## 代码放哪

**代码不进知识库。** 知识库只放设计决策和关键片段（同 [[Ⅰ、从Socket+动态代理开始]] 的做法），完整工程放独立仓库，暂定 `~/Documents/work/quant`。

## 每章的内部结构与验收标准

统一骨架：**`# 引入`（痛点）→ `# 一、二、三`（设计决策，带方案对比表和"思考"引用）→ 核心代码片段 → `# 问题记录`（踩坑清单）**。单篇 250~400 行。

### Ⅰ、看不懂 K 线也能做量化——先把 K 线拆成数字

1. 引子：量化交易员为什么不看图
2. K 线 / 分时 / 盘口到底是什么（OHLCV、tick、买卖盘）
3. 收益率：唯一可比较的度量（算术 vs 对数，为什么必须用对数）
4. 波动率、最大回撤、夏普：三个数说清一个策略好坏
5. 标的体检脚本：跑出分布、回撤、与买入持有的对比
6. 认知转换：策略 = 对未来概率分布下注，不是预测涨跌
7. 问题记录

**验收**：能对着任意一个标的，说清它过去 5 年的年化收益、最大回撤、夏普，并解释"为什么高收益不等于好"。

### Ⅱ、数据是第一生产力——行情数据的七个坑

1. 坑 1：K 线是怎么被"造"出来的（成交聚合、时间边界、未完成 K 线）
2. 坑 2：时区与时间对齐（UTC vs 交易所本地时间）
3. 坑 3：缺失与空洞（停牌、断线、零成交量）
4. 坑 4：复权（股票必须复权，加密为什么不用）
5. 坑 5：幸存者偏差（退市标的去哪了）
6. 坑 6：重复与幂等（增量更新重跑会不会翻倍）
7. 坑 7：数据源差异（同一时刻两个交易所价格不同）
8. 落库设计：Parquet 分区 + 增量水位 + 校验和
9. 问题记录

**验收**：重跑三次增量更新，数据条数和校验和完全不变；随便抽一天，能对上游原始接口逐一核对上。

### Ⅲ、回测引擎（一）——从信号到净值曲线

1. 回测的本质：一个按时间推进的循环
2. 设计决策：向量化 vs 事件驱动，为什么最后要两个都要
3. 撮合模型：信号在 T 产生，成交应该在 T+1 开盘还是 T 收盘
4. 手续费与滑点：建模方式决定策略生死
5. 三本账：持仓 / 现金 / 净值（含浮盈浮亏）
6. 指标计算：年化、夏普、最大回撤、胜率、盈亏比
7. 输出：一份能拿去质疑自己的回测报告
8. 问题记录

**验收**：同一份数据、同一份策略，向量化和事件驱动两条路都能跑通，且零成本、零滑点时结果**逐笔一致**。这个一致性是后面所有结论的地基。

### Ⅳ、回测引擎（二）——让回测变假的五种方式

1. 未来函数：最隐蔽也最致命
2. 幸存者偏差：只在活人身上回测
3. 过拟合：参数高原 vs 参数孤峰
4. 样本内外切分与 Walk-forward
5. 成本敏感性：手续费翻倍还赚吗？滑点翻三倍呢？
6. 实证：为什么向量化说年化 80%，事件驱动只有 20%
7. 问题记录

**验收**：能主动在自己的回测里找出至少一个未来函数，并给出修复前后的收益差。

### Ⅴ、策略：从想法到可证伪的假设

1. 策略的解剖：信号 / 仓位 / 出场 / 风控四件事
2. 四大类：趋势、均值回归、套利、做市（各自靠什么赚钱）
3. 均线交叉：最简单的趋势策略，为什么它不赚钱
4. 时序因子 vs 截面因子（一个标的 vs 一堆标的排序）
5. 接口设计：同一份策略代码，回测和实盘零改动
6. 问题记录

**验收**：同一份策略类，不改一行代码，能分别在回测引擎和 Testnet 网关下运行。

### Ⅵ、风控：活下来比赚钱重要

1. 仓位管理：固定金额 / 固定比例 / 波动率目标 / 凯利公式
2. 三层限额：单笔、单标的、总敞口
3. 熔断与 kill switch：什么情况下必须停机
4. 杠杆与强平：期货/合约的死亡螺旋
5. 风控放在哪一层：策略内 vs 引擎外
6. 问题记录

**验收**：手工注入一个连续亏损序列，风控能在指定阈值触发停机，且所有在途订单被正确撤销。

### Ⅶ、实盘网关：从 Testnet 到真钱

1. 交易所 API 分工：REST 下单 + WebSocket 推行情/回报
2. 鉴权与签名：API Key、时间窗、防重放
3. 幂等：`clientOrderId` 是实盘的生命线
4. 订单状态机：提交 → 部分成交 → 成交/撤单/拒绝/超时
5. 丢单与重试：网络断开时那笔单到底成没成
6. 断线重连与本地状态重建
7. Testnet 全链路演练
8. 问题记录

**验收**：在 Testnet 上跑满 3 天，出现至少一次断线重连，重启后本地持仓与交易所持仓完全一致，无重复下单。

### Ⅷ、对账与偏差：回测与实盘的鸿沟

1. 成交价偏差归因：滑点 / 延迟 / 手续费 / 冲击成本
2. 延迟测量：从信号产生到订单落地用了多少毫秒
3. 每日对账：本地持仓 vs 交易所持仓
4. 偏差量化：回测假设 vs 实盘实际的四张对照表
5. 问题记录

**验收**：连续 10 个交易日，每日自动对账零差异；给出实盘与回测收益差的可量化归因（各占多少）。

### Ⅸ、运维：让平台无人值守地跑

1. 调度：定时任务怎么保证真的跑了
2. 监控指标：心跳、延迟、持仓偏离、PnL、异常率
3. 告警分级：什么时候叫醒你，什么时候只记日志
4. 每日归因报告：赚的钱是哪来的，亏的钱是哪来的
5. 策略失效识别与自动降级
6. 问题记录

**验收**：拔掉网线 30 分钟，恢复后平台自愈；期间发生的异常在告警渠道有记录，且没有产生"幽灵持仓"。

### Ⅹ、进阶路线与常见死法

1. 能力地图：数据 / 因子 / 组合 / 执行 四层
2. 往上的门槛：高频、做市、统计套利各需要什么
3. 常见死法清单（杠杆、过拟合、单一策略、无监控）
4. 从加密换到期货 / A 股，架构要改哪几处
5. 问题记录

# 五、学习节奏与铁律

1. **一次只写一篇。** 每篇写完、跑通、验收通过，再写下一篇。不并行。
2. **先有人工基线，再有策略。** 第三章之前不写任何买卖逻辑，只做体检和回测引擎。
3. **向量化和事件驱动必须对得上。** 零成本零滑点时两者结果不一致，就说明引擎有 bug，不许往下走。
4. **每篇必写"问题记录"。** 踩过的坑不记下来，下次还会踩。
5. **实盘只用亏得起的钱。** 第六章风控没跑通之前，不许上真钱。
6. **不追热点。** 先把一条链路走通，再谈策略好坏——90% 的人死在"策略还没验证就先优化参数"。
